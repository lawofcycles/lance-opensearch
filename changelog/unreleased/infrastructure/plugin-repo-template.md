- The repository carries the governance and contributor files every plugin repository in the opensearch-project organization has: `CODE_OF_CONDUCT.md`, `CONTRIBUTING.md`, `SECURITY.md`, `MAINTAINERS.md`, `ADMINS.md`, `RELEASING.md`, a `DEVELOPER_GUIDE.md` (JDK, build, the three test tasks, the precommit checks, debugging, building against another OpenSearch version), issue templates for bug reports, feature requests and proposals, a `release-notes/` directory with its naming convention, and the organization's check list on the pull request template. `README.md` follows the organization's section order. The `build` workflow file is now `.github/workflows/CI.yml` (the job and the required status check keep the name `build`), and three workflows that need no external setup join it: a weekly and per pull request markdown link check (`links.yml`), the `untriaged` label on new issues (`add-untriaged.yml`) and the cleanup of merged `backport/*` branches (`delete_backport_branch.yml`). `RELEASING.md` lists the workflows that wait for the organization's secrets (`backport.yml`, `auto-release.yml`, `maven-publish.yml`).
