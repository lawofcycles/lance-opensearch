- Unreleased changelog entries are recorded as fragments under `changelog/unreleased/<section>/<topic>.md`, one file per pull request, instead of being appended to the `## [Unreleased]` section of `CHANGELOG.md`. Every parallel pull request used to append to the same lines of that section and rebase onto `main` failed with a conflict there on nearly every merge. The `changelog` workflow fails a pull request that neither adds a fragment nor carries `skip-changelog` (as a label or as a line of its own in the description) and validates the fragment tree with `scripts/assemble-changelog.py --check`; at release time the same script concatenates the fragments in section order into a `## [X.Y.Z] - date` block, carrying any entries still written under `## [Unreleased]` ahead of them, and removes the consumed fragments.
