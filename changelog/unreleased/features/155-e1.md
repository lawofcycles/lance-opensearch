- The planner reads table statistics collected from Lance metadata instead of a bare row count. Once per manifest version a node collects the fragment list (live rows and data files per fragment), the deleted row count, and per column the indexes that cover it with their type, fragment coverage, size and Lance's index statistics (indexed and unindexed rows; the bitmap count of a bitmap index as the column's distinct value estimate); zone maps are read lazily per column. The statistics are cached per (table URI, manifest version) and dropped when the version's snapshot closes. `LanceTable.getStatistic()` answers the live row count from them and Lance `RowCount` / `DistinctRowCount` metadata handlers for the scan sit in front of Calcite's defaults. Cost coefficients and plan selection are unchanged. `GET /_lance/stats` gains `plan.statistics.tables` (entries held) and `plan.statistics.collect_millis_total` (time spent collecting). (#155)
