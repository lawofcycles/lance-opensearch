- The aggregation routing settings are cost inputs of the planner instead of gates in front of it. `lance.aggregation.pushdown` and `lance.aggregation.pushdown_max_groups` travel to the Volcano run in `CostInputs` next to the parallelism settings; a pushed aggregate costs infinity when the setting is off or when the statistics based group estimate of the tree exceeds the bound, so the planner implements the aggregate through `LuceneAggregateExec` and `GET /<index>/_lance/explain` shows that choice as a cost decision with nothing reported as `unplanned`. The coordinator no longer pre decides which aggregation trees the planner may see: the structural allow list (`LanceAggregationSupport.isPushdownCandidate`) is gone and the translator's acceptance is the only shape check, so the same request plans the same way on the coordinator, on explain and in the unit tests. The pushdown rule no longer refuses a `cardinality` metric; such trees are pushed like any other and lose the cost comparison to the aggregators, through the fitted coefficients on tables of a million rows or more and through a documented placeholder penalty below that range, so the observable plan is unchanged and a faster pushed implementation would change it by changing the coefficients. The executor keeps `lance.aggregation.pushdown_max_groups` as a node local guard on the group estimate it builds from the request shape, counted as `plan.refinements.aggregate_resolution` when it refuses.
