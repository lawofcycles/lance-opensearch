- The coordinator prunes fragments by Lance zone map statistics before it ships the plan. When a column the query filters on carries a zone map index, `RequestPlanner` hands the query predicate of the logical tree to `ZoneMapPruner`, which reads the zone map the table statistics memoised (per zone minimum, maximum and null count) and lists every fragment none of whose zones can hold a matching row under `FragmentPlan.excludedFragmentIds`: a comparison whose literal falls outside every zone's bounds, an `exists` over all null zones, an all null zone under any comparison, `bool` `must` / `filter` clauses combined as a union and `should` clauses as an intersection, on integer, float, boolean, keyword, date and timestamp columns and struct children. A fragment the zone map does not cover, a zone with unknown or `NaN` bounds, a `must_not`, a pattern query and a `post_filter` never exclude anything, so a result never changes; only the fragments the executors open do. The exclusions apply to every physical form (pushed page, pushed aggregate, full text and `lance_knn` prefilter, Lucene collectors, count). Each data node's executor drops the excluded fragments from the list the coordinator sent before it opens the fragment reader or any Lance scan, answers over a reader with no leaves when every fragment of its share is excluded, and counts the skipped fragments under `plan.pruned.fragments` in `GET /_lance/stats`; `GET /{index}/_lance/explain` shows the list as `fragment_plan.excluded_fragment_ids`. The zone maps are read once per manifest version and only for the columns the query names, while the coordinator (or the explain endpoint's model construction) holds the table open. `FragmentPlan.WIRE_VERSION` is `2` (the excluded fragment ids follow the pushed aggregate as an integer array) and `LanceNodeStats.WIRE_VERSION` is `2` (the pruned counter follows the executed counters). Bloom filter indexes are not consulted. (#15)
