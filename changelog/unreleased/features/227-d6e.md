- The fragment path is the only search path over a Lance backed target. The dispatch filter no longer forwards a search body it does not serve to OpenSearch's stock shard search over the whole table reader; it decides only whether every target is Lance backed, and the coordinator plans every body. A body carrying `suggest` or `highlight`, the two elements that need full text APIs the Lance Java SDK does not surface, answers 400 `illegal_argument_exception` naming the element (``search body carries a `suggest` clause which needs full-text APIs Lance does not surface. See `docs/limitations.md`.`` and ``search body carries a `highlight` clause which needs full-text APIs Lance does not surface.``) before a table is opened, on every table size, instead of running on one shard's reader or being refused only above the Lucene document bound. The planner's shard path convention, its `ShardPathFallbackExec` operator, the `PlanToShardPathRule`, the `LanceShardPathShape` marker and the `ShardPathReason` constants are gone, as is the Volcano run the filter used to start on the transport worker for every request. The stock search action still serves a target that mixes a Lance backed index with an ordinary one. `docs/limitations.md` names the refused elements and their messages. (#227)
