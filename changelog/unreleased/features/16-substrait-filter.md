- Scalar filters reach the Lance scan as Substrait `ExtendedExpression` bytes (`ScanOptions.substraitFilter`) next to the Lance SQL string the planner printed before. The filter pushdown rule registers both encodings of a predicate as alternatives of one plan, the cost model orders them by their size on the wire with a tie break for the Substrait form, and a filter Lucene's collector or aggregators run over takes the same comparison, so a `term`, `range` or `bool` query now ships as Substrait on a small fan out and as SQL when a very long term list on a wide cluster makes the bytes the larger cost. Lance decodes either encoding into the same DataFusion expression, so results and `hits.total` do not change; the Substrait encoding addresses columns by position and accepts arithmetic the SQL printer refuses, while a struct child predicate, a full text or knn prefilter, a pushed sorted page and the filter under a pushed aggregate stay SQL. `GET /<index>/_lance/explain` reports the choice as `filter_substrait_bytes` next to `filter_sql`, and `FragmentPlan`'s wire version moves to 2 for the new field.
