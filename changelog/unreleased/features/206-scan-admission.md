- One admission gate for every native scan and index load of the fragment path, so a table larger than the node answers 429 instead of ending the node with a kernel OOM kill. `ScanAdmission` (the former `FtsAdmission`) keeps the one decision the full text gate had (the node's `MemAvailable` plus the memory earlier admitted scans retained, minus `lance.admission.headroom`, must hold the estimate) and gains one estimator per path, each with its formula in the Javadoc and its coefficients as named constants: `scalar_index` (the BTree pages, bitmaps or zone map Lance loads to answer a filter, from the index's manifest size and the filter's selectivity), `filter_scan` (the row addresses a filtered scan materialises, the batches in flight and the read queue, for `LanceScanFilterQuery` and the sorted top-k page), `vector_index` (the IVF partitions a `lance_knn` probes, loaded twice while they are concatenated, and the refine reads), `aggregate_scan` (the read queue and batches of every parallel scan of a pushed aggregate), and `column_load` (the heap copy the request breaker already judges, recorded under the gate's stats). Heap terms (a filter's per fragment bit sets, an aggregate's group state) are judged against the request breaker's room and named in the message. An estimate at or below the index cache shard share is zero for every kind, so small tables are never gated; `lance.test.index_cache_shard_share` makes the integration tests declare a fixture as not fitting. A request that runs several gated paths is judged per path and counts once in flight, and every gated scan brackets itself so the retained pool samples its completion. (#206, #35)
