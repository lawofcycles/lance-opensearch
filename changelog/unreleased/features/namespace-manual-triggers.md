- Two manual triggers for the two background jobs, so an operator does not wait on `lance.namespace.poll_cadence`. `POST /_lance/namespace/_poll` (optional `?name=<registration>`) runs one catalog listing cycle now on the elected cluster manager and answers the indexes it surfaced, the tables it skipped with the reason (name collision, allowlist, resurface guard, failed create) and the registrations whose listing failed; action name `cluster:admin/lance/namespace/poll`. `POST /{index}/_lance/sync` runs the freshness check of one index now on the node that holds its shard and answers `moved`, `served_version`, `target_version`, `mapping_changed` and `rebuilt`; action name `indices:admin/lance/sync`. Both are idempotent.
