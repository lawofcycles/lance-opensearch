- Each request plans once at the coordinator and the fragment executors run the shipped plan. The coordinator rewrites the query with the shard-free rewrite the shard path applies, translates the whole body through the same entry the explain endpoint uses, runs the Volcano planner once per target and ships the per node physical form with every fragment request as a `FragmentPlan` (the Lance SQL of the scalar predicate, the full text or `lance_knn` clause the executor builds its Lance query from, and the pushed page or the pushed aggregate with its Substrait bytes). The data nodes no longer plan: they apply the guards only they can judge (a reader wrapper, the Lucene sort field types, the aggregate's resolution against the mapping) and downgrade a pushed operation to Lucene where it cannot run there, never the other way, so the physical plan `GET /<index>/_lance/explain` prints is the plan that executes. Downgrades are counted per reason under `plan.refinements` (`security_wrapper`, `sort_field_type`, `aggregate_resolution`, `column_store_warm`) in `GET /_lance/stats`, and `plan.executed` next to it counts fragment requests the Lance scan answered (`pushed_scan`) and the ones Lucene answered (`lucene`); the executor logs the planned and the executed plan at debug level under `lance.plan`. Response shapes, routing, error messages and status codes are unchanged; the per node plan is a wire format internal to the plugin, so every node must run the same plugin version and a rolling upgrade is not supported for the fragment path.
