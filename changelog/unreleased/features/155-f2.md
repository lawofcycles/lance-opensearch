- `GET /<index>/_lance/explain` prints, on every physical operator line of `physical`, the `Accuracy` and `TieStability` the operator declares and the cost the planner charged it (`accuracy=[EXACT], tie_stability=[STABLE_KEY], cost=[{ms=..., native_bytes=..., heap_bytes=...}]`, two significant digits), with the root carrying `total_cost`, the cumulative figure the Volcano run compared. The response gains a top level `traits` object (`requested`: what the body demanded, `APPROXIMATE` / `NONE` when nothing did; `declared`: the plan root's values; `enforcer`: `none`, or which request element demanded which value, what the cheapest plan offered and whether a costlier plan was chosen or none declares it) and answers a body no plan meets with 200 instead of 400: `physical` shows the cheapest plan the demand refused, `unplanned` carries the `plan_failed` message `_search` still answers 400 with, `fragment_plan` is absent and `traits.enforcer` names the refusal. `refinements_possible` is sorted in reason order (`security_wrapper`, `sort_field_type`, `aggregate_resolution`, `column_store_warm`). The `FragmentPlan` and `LanceExplainResponse` streams open with a `WIRE_VERSION` marker (`1` for `FragmentPlan`, bumped to `2` for `LanceExplainResponse` by D-6e when the reasons list of the retired fallback route was dropped and the plan texts and the traits became optional for the unsupported route) that a reader of another version refuses with a message naming both numbers, so a fragment request between plugin versions fails at the first field instead of as a stream corruption. `docs/query-plan.md` is the new reference for the plan: the explain fields with an example, the physical operators, the cost model, the refinements and their order, the traits and the wire format; `docs/features.md` links to it and `docs/architecture.md` points at it.
