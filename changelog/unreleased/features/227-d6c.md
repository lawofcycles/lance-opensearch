- Pipeline aggregations run on the fragment path. Every sibling pipeline (`avg_bucket`, `sum_bucket`, `min_bucket`, `max_bucket`, `stats_bucket`, `extended_stats_bucket`, `percentiles_bucket`) and every parent pipeline (`cumulative_sum`, `derivative`, `moving_fn`, `moving_avg`, `serial_diff`, `bucket_sort`, `bucket_script`, `bucket_selector`) is computed once on the coordinator, after the per node aggregation trees have been reduced: `MergeReducer` reduces them through `InternalAggregations.topLevelReduce` under the final reduce context carrying the request's pipeline tree, the reduce `SearchPhaseController` runs for the shard path, so a request with a pipeline fans out to every data node instead of reading the whole table on one node through the shard path, and its answer equals the shard path's for every shape. Core's refusals (`bucket_sort` set to perform nothing, a `buckets_path` naming no aggregation, a script that does not compile) answer the same 400 on both paths. The `ShardPathReason` constant `PIPELINE_AGG` is gone. (#227)
- A search over several Lance backed indexes with aggregations runs on the fragment path: the coordinator fans out once per index and reduces the indexes' aggregation trees together with the same stock reduce, where the dispatch filter used to send any aggregation over more than one index to the shard path. A target mixing a Lance backed index with an ordinary index or an alias to one keeps the shard path, unchanged. (#227)
