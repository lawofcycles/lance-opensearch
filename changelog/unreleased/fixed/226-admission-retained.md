- The full text admission gate credits the memory earlier admitted scans left in the process when it judges the next one. An admitted unbounded scan over an inverted index that does not fit the index cache shard leaves the posting lists and per partition document row ids Lance cached next to the refused entry and the pages the allocator kept, so `MemAvailable` reads lower after the scan than before it while the next scan of the same table needs that much less fresh memory; the gate used to judge the repeat against the lowered reading alone and refused it with 429, so a 128 GB node served one unbounded full text aggregation over a 1B row table per process lifetime. `FtsAdmission` now keeps a per node pool of the `MemAvailable` an admitted scan consumed between its admission and its completion, capped by the process resident set growth over the same interval, bounded by the largest admitted estimate, decayed as `MemAvailable` recovers, suspended while a gated request is in flight or a full text scan runs, and withheld when the resident set exceeds `lance.native_memory.limit` plus the heap by more than the pool. The decision compares the estimate with `MemAvailable - headroom + pool`, the 429 message names the credited figure, and `GET /_lance/stats` reports it as `fts.admission.retained_bytes`. (#226)
