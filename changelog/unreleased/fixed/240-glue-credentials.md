- A `glue` namespace registration without static keys in its `config` now authenticates from the shared credentials and config files of the OpenSearch process user (`~/.aws/credentials`, `~/.aws/config`), the same way the other sources of the AWS SDK's default chain already worked. The Java agent judges a file read against every protection domain on the calling thread's stack, and the poll and the tables preview reach the Glue client through server frames that hold no grant under the user's home, so the SDK's read of the profile file during the client build was denied whatever the plugin policy said: the registration stayed `unavailable` with the error `Denied OPEN (read) access to file: /home/<user>/.aws/credentials` and no table surfaced. The plugin policy now grants `read` on `${user.home}/.aws/-` (nothing else under the home, no write or delete), and the catalog client build (`LanceNamespaceFactory.create`) and every catalog call (`LanceNamespaceHandle.call`) run inside `doPrivileged`, which stops the agent's walk at the plugin's own jars. The Iceberg REST, Polaris and Unity clients read no local file and are unaffected. (#240)
