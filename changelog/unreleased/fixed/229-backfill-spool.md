- The `type: text_analyzer` backfill no longer spools the derived tokens column to `java.io.tmpdir` before `AddColumns`, and no longer tokenizes on one thread. The producer is a streaming Arrow reader that Lance's `AddColumns` pulls batch by batch: the source column is scanned in fragment order, each 4,096 row batch is tokenized as one task on the generic pool with at most `lance.attach.backfill_threads` running at once (new node setting, dynamic, default half the CPUs the JVM sees), and the token batches are emitted in source order into the table's own data files. Nothing is written to a local disk, so a 1B row backfill no longer fills the node's root or data volume nor trips the flood stage watermark, and memory stays bounded by the batches in flight. On a 20M row table (250 byte values, `english` analyzer) the backfill went from 126 s on one thread with a 5.1 GB spool to 29 s on 16 threads with no spool, on the same 32 core machine. The attach request is now a cancellable task, so `POST _tasks/<id>/_cancel` on a `derive: sync` attach stops the backfill between two batches and the pending commit writes nothing; the `derive: async` response gains `backfill: {estimated_bytes, spool_path: "none", threads}`.
