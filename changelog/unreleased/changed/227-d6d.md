- The aggregation types the fragment executors cannot run answer 400 `illegal_argument_exception` at the coordinator and from `GET /{index}/_lance/explain` instead of routing the request to the shard path: `global` (the shard path collects it in a pass of its own over every document, which the executor's single collection under the request's query does not run), `top_hits` (needs the search context's fetch phase), `rare_terms` (its aggregator seeds itself from the shard id) and `significant_terms` / `significant_text` (background frequencies from an inverted index Lance leaves do not carry). The message names the builder (`aggregation type [global] on [g] is not supported for Lance-backed indices: ...`). The decision lives in the coordinator's translator (`AggregationToRel.checkExecutable`, reached through `SearchRequestToRel.checkAggregationsExecutable`); `LanceAggregationSupport` and its `isSupported` allow list are gone, and the pushdown shape predicates the executor still uses moved to `AggregatePushdownShapes` next to `AggregateSpecResolver`. `docs/limitations.md` lists the refused types with their reasons.
