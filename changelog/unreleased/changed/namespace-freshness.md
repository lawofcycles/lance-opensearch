- Table freshness moved off the elected cluster manager to the node that holds the index's shard. The manager's namespace poll now only lists the registered catalogs and creates an index for every table that has none; it opens no other table. Every started Lance backed shard registers with a per node `LanceIndexFreshnessService` through the shard lifecycle hooks and is checked at `lance.namespace.poll_cadence`: the check opens the latest manifest, resolves the followed tag, compares with the version the shard reader serves and, when they differ, re-derives the mapping, refreshes the shard and retires the previous snapshot. A mapping update is sent only when the derived mapping differs from the mapping the index has (a preflight merge into the shard's mapper service decides), so an append without a schema change no longer creates a cluster state update task per index per version. The first check after a shard starts derives once even without a move, which replaces the manager's in memory served version table and the adoption scan that rebuilt it after a restart or a failover. The keyword to `lance_text` rebuild, the `node_local` reader advance and the `wait` policy warning moved with the check. `GET /_lance/stats` reports the checks per node under `freshness` (`tracked`, `checks`, `moves`, `mapping_updates`, `mapping_unchanged`, `rebuilds`, `failures`, `last_check_millis`). `docs/design/namespace-freshness.md` records the decision and the direction it points at.
